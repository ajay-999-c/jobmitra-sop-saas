# Stage 3 Candidate Desk schema — pending Windows approval

Revision `0004_candidate_desk`; parent `0003_jd_work_focus`. Exactly seven new tables; no alterations to existing business tables. All relationships use `ON DELETE RESTRICT`.

UUIDs are generated by SQLAlchemy. `created_at` defaults to PostgreSQL `now()`; editable rows maintain `updated_at` through SQLAlchemy. Candidate/request `version` fields provide optimistic conflict checks. There are no deletes in the API and no global unique mobile constraint.

No eighth history table is included. See the implementation review for the separately proposed `candidate_events` table.
